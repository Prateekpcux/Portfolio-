The problem

The problem wasn't finding assets.
It was trusting them.

Before Periscope

Six platforms. Zero coherence.

  • Power BI, Tableau, Signal 1, Vizient, Epic, SharePoint, no shared taxonomy
  • Duplicate reports everywhere, no one knew which version was official
  • Users emailed the analytics team before trusting any asset
  • AI models with no governance, oversight, or expiry tracking
  • New employees had no onboarding path into analytics
High bounce off stale reportsDuplicate workLow data trust
The mandate

One governed marketplace. Every asset. Trusted.

  • Unified search and browse across all six platforms and asset types
  • Certification state visible on every asset card, not buried in metadata
  • Dedicated AI model inventory with oversight, performance, and approval chain
  • Campaigns path for clinical users who think in outcomes, not taxonomies
  • Governance workflows for admins, certify, deprecate, manage lifecycle

Key decisions

Three decisions that mattered most.

Research surfaced the findings. These three decisions are what we did with them.

01

Governance visible at card level, not the detail page

  • Early prototypes buried certification in a metadata tab
  • Users scrolled past it every single time
  • Fix: elevated to the card surface, status, owner, last validated, all visible at browse time
Trust at browse time
02

Campaigns, a parallel browse path for clinical users

  • Clinical users think in initiatives, not data taxonomies
  • Taxonomy browse failed them in every session
  • Fix: a Campaigns path that groups assets by HIMSS, Cost Reduction, Heart Failure
2x faster time-to-asset for clinical users
03

AI models treated as first-class assets, not a filter

  • Initial scope made AI just one asset type in the filter panel
  • AI carries oversight obligations no other asset has
  • Fix: a dedicated inventory with performance, expiry, bias review, oversight chain
Inova's first AI governance UX

Design system

Built on Inova's design system.

Periscope was built entirely within Inova's enterprise design system, the Arial typeface, semantic color tokens, and established component patterns. My job wasn't to invent new styles; it was to extend the system with the patterns a marketplace needed that didn't exist yet.

Asset cards

Trust-first browse tile, certification badge, tool source icon, owner, last validated, all visible before clicking

AI model cards

Performance state, certification expiry countdown, bias review flag, no equivalent in the base system

Governance chips

6-state certification mapped to Inova semantic tokens: Certified, In Review, Expired, Pending, Deprecated, Flagged

Campaign tiles

Initiative-grouping built from existing card components, with a new hero image treatment for clinical pathways

Extended patterns added to the system
Certified
On the card surface, green badge, owner, last validated
In review
Blue indicator, governance workflow in progress
Expired / Flagged
Red, visible before the user opens the asset, not after
Deprecated
Grey, surfaced in search to redirect, not hide

The Inova system Periscope extended, color, type, iconography, and components.

Outcomes

Two numbers that mattered most.

68%
Faster time-to-find an asset
How we measured it
  • Timed task: find a specific certified dashboard in the old system (Power BI + SharePoint + Teams) vs Periscope
  • Old system avg 6.2 min, Periscope avg 2.0 min, across 3 rounds of moderated testing
  • The driver: governance status on the card meant users stopped second-guessing which asset to trust
20K+
Active users at launch
How we got there
  • Replaced Power BI, Tableau, Signal 1, Vizient, Epic, and SharePoint in a single Phase 1 deployment
  • Clinical users adopted via Campaigns, finding audit assets without learning a new taxonomy
  • Zero formal training sessions required, the experience was intuitive enough to self-onboard
Periscope replaced scattered report hunting with one searchable, governed marketplace. The hard part wasn't making assets easier to find, it was making people confident that what they found was certified and safe to use for clinical decisions.
Next steps
  • Moderated usability testing with 5 clinical users post-launch
  • A/B testing, search placement and card layout variants
  • UAT validation and dev sprint support
  • Iterative feedback loops to refine based on real usage
What I'd do differently
  • Push for moderated user research before Sprint 1, not after
  • 5 clinical users early would have validated trust-first cards 2 sprints sooner
  • Stakeholder input was strong, but real users would have accelerated decision confidence
